# Development - Plan

## Planning Philosophy
The planning phase will define the entire outset and eventually outcome of the project. It's crucial to spend the right time doing the up front analysis and architecture to get the technical plan in place with a well defined backlog, without falling into paralysis analysis.

Key focus areas include:

- Technical design documentation
- Requirements gathering and refinement
- Backlog creation and grooming
- ALM tool setup (JIRA) and process definition

While comprehensive planning reduces risks and improves delivery quality, avoid over-planning. The team should:

1. Set clear timeboxes for planning activities
2. Define MVP requirements early
3. Document essential technical decisions
4. Move forward with development when requirements are "good enough"

Remember: Planning is iterative. Initial designs and requirements will evolve through the SDLC's observe phase, providing opportunities for refinement based on real-world feedback.

## What is an ALM
ALM (Application Lifecycle Mangement) is a class of tools that are designed to collect backlogs of work items in task boards for the team to work from and reference. These work items move through lifecycle states as they move through the SDLC pipeline. An ALM that is well set up with a well defined process that is fully adopted by the team can do wonders for production. You can expect to benefit from:

- decreased cycle time spent on development
- faster deploys to production
- clearer hand off between teams
- improved communication and visibility to tasks and their progress.

It is essential that your ticketing process works for the team and is not a bottleneck. Especially in greenfield deveopment, not having a sufficient backlog can end up being a bottleneck for engineers, who need requirements to move as fast as possible. On the other hand, spending too much time in refinement attmepting to flesh out a full backlog runs counter to agile development and takes away from development time as well. The trick is a to achieve a balancing act; don't strive to get it right the first time, strive to enable a process that facilitales rapid development and deploy so developers achieve the solution the client needs sooner.

### Common Task Management Tools
Popular task management and ALM tools include:

- **JIRA**: Widely used for agile project management, particularly in software development
- **Azure DevOps (ADO)**: Microsoft's integrated development platform with robust work tracking
- **Shortcut** (formerly Clubhouse): Modern project management tool focused on software teams
- **Trello**: Simple, visual task management using Kanban-style boards
- **Linear**: Fast, streamlined issue tracking designed for tech teams
- **GitHub Projects**: Native project management integrated with GitHub repositories
- **GitLab**: Built-in issue tracking and project management features
- **Monday.com**: Flexible project management platform suitable for various teams
- **Asana**: Versatile task and project management tool
- **ClickUp**: All-in-one project management with customizable views

# I wish I had
When it comes to planning, I find projects are more successful when they: 

- add swimlanes (verticle columns) to denote the lifecycle of a work item, as it moves though ready for development, in development, ready for QA, and so on.
- Don't worry about assigning point values or metrics to work items, a more reliable pieces of data is cycle time on a ticket, rather than relative and estimated complexity
- maintain a backlog that goes through regular groomings and has tickets that are filled out with complete mvp requirements. In greenfield dev, this can often be challenging, but tickets can evolve as they are worked on, and so can the requirements
